NumX Max · Code signing policy

项目：NumX Max · Digital Artisan Market（Apache-2.0 代码，CC-BY-4.0 文档）。本页同时是桌面端签名与下载政策页。

当前状态：SignPath Foundation OSS 申请处于准备／申请阶段。申请批准、签名请求完成并通过 Windows 验证前，现有 EXE 均按未签名预验包处理，不得称为可信发布者版本。

签名服务与审批

Windows 组织运行时安装包的签名服务目标：Free code signing provided by SignPath.io, certificate by SignPath Foundation。

  • Authors / Committers / Reviewers：@jwpy299 与 CODEOWNERS／DSH 独立复核流程；外部贡献必须经维护者评审。
  • Approvers：@jwpy299（Owner 单签）。每次签名请求必须人工审批，并绑定最终 commit SHA、workflow run、未签名制品 SHA-256 和签名后制品 SHA-256。
  • 只接受由公开仓库最终 commit SHA 对应的 GitHub Actions 构建。旧 SHA 的签批不能用于新 SHA，禁止上传本地 EXE 直接签名。

发布门禁

  1. 构建、测试、secrets／许可证扫描通过后，才把 GitHub Actions artifact 提交 SignPath。
  2. Windows EXE 必须具有有效 Authenticode 签名和 RFC3161 时间戳，并在真实 Windows VM 中验证可信证书链。
  3. 安装、启动、卸载、升级、回滚证据必须绑定最终 commit SHA 和制品 SHA-256。文件改名、自签名、OAuth／申请页面均不算完成。
  4. 签名审批与生产上线审批是两个独立步骤；全部证据闭合后才允许正式启动生产上线。

下载与隐私

NumX Max 下载注册中心 · 平台隐私政策 · 公开 Releases

构建与签名阶段向 GitHub 和 SignPath 提供源代码、构建元数据及待签名制品；不把最终用户业务数据、生产密钥或 canonical 数据放入签名制品。桌面端实际网络行为以平台隐私政策及各启用 Agent 服务的配置为准。
